# 画面の文言

画面に出す文字列（見出し、ボタン、通知、空の状態、`aria-label`、OAuth の画面、`window.confirm` など）を足すか変えるときに読む。
余白や操作の規則は [design.md](./design.md) にある。

文字列を足すときは、既存の同じ場面の文を `rg` で探し、形と語をそろえる。
既存の文が下の規則と食い違うときは、既存の文でなく規則に合わせる。

## 形

- 句点は、文の長さでなく役割で決める。
  見出し、ボタン、ラベル、プレースホルダー、上端の保存の状態には付けない（「ログインの期限が切れました」「タイトルを入れて欄を離れると作成します」）。
  本文の段落と `role="status"` の文は、敬体（です、ます、ました）で終わるなら付ける（「公開しました。」）。
  体言止めの短い状態表示には付けない（「ログインの期限切れ」）。
- 進行中は「〜中…」にする（「保存中…」「公開範囲を変更中…」「画像を添付中…」）。
  「…」は進行中にだけ使う。
  公開と下書きの切り替えは、状態に読めないよう「公開に変更中…」「下書きに変更中…」と書く（「公開中…」は公開している状態に読める）。
  見える読み込み中の表示は、何を読んでいるかを付ける（「ページを読み込み中…」「一覧を読み込み中…」）。
  枠や見出しで対象が分かる読み上げ専用の文は「読み込み中…」でよい。
- 日時の詳細は `YYYY/MM/DD HH:mm` で書く。
  SPA は端末の時刻で、タイムゾーンを書かない。
  OAuth の画面は UTC で、末尾に「 UTC」を付ける（「許可: 2026/10/20 19:09 UTC」）。
  一覧の短縮表示と「3分前」のような相対時刻は使ってよい。
  ISO の形は出さない。
- 数は半角にし、4 桁以上は桁区切りを付ける。
  数と漢字や仮名の間は空けない（「3文字以上」「約1時間前」）。
  欧文の語（token、UTC など）と、欧文の単位を付けた数（「10 MB」）は 1 語として扱い、和文との間を空ける。
  件数は「件」、ページ数は「ページ」と書く（「書き換えたページ（3件）」）。
  数と単位を別の行に分けない規則は描画の規則なので、[design.md](./design.md) にある。
- `aria-label` は、名詞句か、押した結果が変わらない動詞句にし、見える文字を含める。
  開閉や選択の状態は `aria-expanded` などに任せ、名前に動詞を入れて状態を二重に読ませない。
  値を添えるときの区切りは半角の「: 」にする（「ページを検索: 検索語」）。
  意味のある子要素を持つ枠には、固定の `aria-label` を付けない（子の名前が読まれなくなる）。
- 同じ出来事を、上端の状態と通知の 2 つの live region で読ませない。
- 同じ出来事には同じ文を使い、定数を共有する（`apps/web/src/pages-api.ts` の `RELOAD`）。

## 語

| 場面 | 使う語 | 使わない語、補足 |
| --- | --- | --- |
| 公開と下書き | 公開範囲 | 公開設定 |
| 切れたときのログイン | ログインし直す（見出しは「ログインの期限が切れました」） | 最初のログインは「ログイン」 |
| 保存できなかった内容を端末に置くこと | この端末に残す（残してあります、残せませんでした、残った内容） | 退避、一時保存（「保存できません」と並ぶと保存したと読める） |
| 競合の 2 つの内容 | 別の場所の内容、この画面の内容 | サーバー、手元、版、取り込む |
| 競合の解消の操作 | 使う、置き換える、上書きする | |
| 捨てる操作 | 破棄する（競合の確認と、端末に残った内容） | 捨てる |
| 削除の確認 | 「未保存の変更も含めて、元に戻せません。」 | |
| OAuth で接続する側 | アプリ（`client_id` は補足にだけ残す） | クライアント |
| 制御文字と NUL | 見えない文字 | |
| 一覧に戻る導線 | 一覧へ戻る（検索を解除する場合は「検索を解除して一覧へ戻る」） | 一覧の見出しは並び順で変わるので、見出しの名前では呼ばない |
| 添付 | 添付 | アップロード |
| 他のページのリンクの更新 | 書き換え | 更新（ページ自体の更新と紛れる） |
| 再読み込み | 再読み込み | 「ページを再読み込み」（「ページ」が wiki のページと紛れる） |
| 画面の操作 | 押す | クリック（タッチの端末に合わない） |
| 通信の確認 | 通信環境を確かめる | 通信を確かめる（普段言わない） |
| HTTP の番号 | 5xx とその他の 4xx は「（HTTP 503）」のように残す | 429 は番号を出さず、混雑の文にする（「一時的にアクセスが制限されています。」） |

## 判断

- 名前で分かることに説明を足さない。
  「下書き」「公開」の名前があれば、公開すると owner 以外にも見えることは書かない。
- 仕組みの語は、別の語で正確に言えるなら画面に出さない（サーバー、版、退避、draft、匿名、トークンなど）。
  履歴の画面では、履歴の 1 件を指す語として「版」を使う（「この版の本文に戻す」）。
  履歴の画面の外（編集画面の状態や通知など）では、版を「本文」と言い換える（「本文を戻し中…」）。
- 「作成」は、押した時点でページができる操作にだけ使う（「このタイトルで作成」「「検索語」を作成」）。
  title を渡した新規作成は、開いた時点で作るので「作成」でよい。
- 失敗の原因は、確かなときだけ書く。
  リンク先を開けなかった知らせは、通信の失敗でも別の失敗でも同じ結果（error）になるので、通信を原因として書かない（`apps/web/src/title-resolver.ts`）。
  添付、リンクの書き換えの停止、画面の読み込みの失敗も、通信以外の失敗が同じ結果にまとまるので同じ書き方にする（`apps/web/src/attachments.ts`、`LinkRewriteStatus.tsx`、`page-view-loader.tsx`）。
- SPA が知らないエラーコードは、サーバーが返した message を出さず、HTTP の状態に応じた汎用の文にする（`apps/web/src/pages-api.ts` の `statusMessage`）。
- そろえないもの: 相対時刻の表記（「3分前」「約1時間前」など）は、画面ごとの文脈が違うのでそろえない。
