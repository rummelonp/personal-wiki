# デザイン

画面の見た目と使い心地で守ることを書きます。
今の見た目を土台にし、シンプルで無駄がなく、少し遊び心のある画面を目指します。

## 原則

1. 本文を主役にします。
   装飾は、情報を持つときだけ置きます。
2. 操作は少なくし、置き場所を画面どうしで揃えます。
   1 つの画面で目立たせる操作は 1 つにします。
3. 余白の刻み、左端の位置、線の太さ、アイコンの大きさと線幅を揃えます。
4. 階層は、文字の大きさと太さの差、それに差し色 1 色で作ります。
   中間の灰色を増やしません。
   エラーや成功を示す状態の色は、差し色に数えません。
5. 遊び心は、押した手応え、保存の点、空の状態の一言、控えめな遷移など、動きと反応に置きます。
   作業の邪魔をせず、`prefers-reduced-motion` で止めます。
6. ダークもライトと同じだけ作り込みます。
   色の反転で済ませません。

## 守る条件

### 見た目

- 見た目の値は `apps/web/src/theme.css` の token に置きます。
  対象と例外の書き方は [AGENTS.md](../AGENTS.md) の規約にあります。
- 同じ役割の要素は同じ見た目にし、focus、hover、押下の表示も揃えます。
- 本文の幅は `--prose-width`（40em）にし、1 行を全角 40 字前後までに収めます。
- Web フォントは使わず、端末のフォントで組みます。
  和文と欧文が混ざっても崩しません。
- 空、読み込み中、エラー、長い title、多いタグ、大きい画像などのどれでも崩しません。
- 画像、コードブロック、通知、ダイアログなどを、ダークで周りより明るく目立たせません。

### 操作

- 読み込みや保存でレイアウトを動かしません。
- タッチ操作の端末では、タップの対象を `--tap-size`（44px）以上にします。
- タッチ操作の端末では、入力欄の文字を `--font-size-input`（16px）以上にし、iOS が focus でページを拡大しないようにします。
- ソフトウェアキーボードで caret を隠しません。
- エディタは日本語の変換を崩しません。
  守る条件は `packages/editor/src/ime.ts` の冒頭にあります。
- 失敗したときは直し方の分かる案内を出し、入力した内容を残します。

### アクセシビリティ

- axe で serious 以上の違反を出しません。
  `apps/web/e2e/a11y.spec.ts` が検査し、既知の違反の一覧（`a11y-known.json`）は空に保ちます。
- 本文と補助の文字のコントラストは、ライトとダークの両方で WCAG AA を満たします。
- 作成、検索、保存の失敗や衝突からの復帰を、キーボードだけで終えられるようにします。

## 確かめ方

- 描き終わった画面だけでなく、読み込み中、保存中、公開中などの途中の状態も見ます。
  Playwright の `page.route` で API の応答を遅らせると撮れます（`apps/web/e2e/sheet/scenes.sheet.ts` に例があります）。
- `pnpm e2e:sheet` で、明暗と幅 375、768、1280 の画面の一覧を見ます。
- 幅 320、375、768、1280、1440 で横スクロールが出ないことは、`apps/web/e2e/layout.spec.ts` が確かめます。
- axe のコントラストの検査はライトでしか走りません。
  ダークの色を変えたら、コントラスト比を手で測ります。
- 動きを足したら、`prefers-reduced-motion` で止まることを確かめます。
