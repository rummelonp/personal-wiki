# デザイン

画面の見た目と使い心地で守ることを書く。
今の見た目を土台にし、シンプルで無駄がなく、少し遊び心のある画面を目指す。

## 原則

1. 本文を主役にする。
   装飾は、情報を持つときだけ置く。
2. 操作は少なくし、置き場所を画面どうしで揃える。
   1 つの画面で目立たせる操作は 1 つにする。
3. 余白の刻み、左端の位置、線の太さ、アイコンの大きさと線幅を揃える。
4. 階層は、文字の大きさと太さの差、それに差し色 1 色で作る。
   中間の灰色を増やさない。
   エラーや成功を示す状態の色は、差し色に数えない。
5. 遊び心は、押した手応え、保存の点、空の状態の一言、控えめな遷移など、動きと反応に置く。
   作業の邪魔をせず、`prefers-reduced-motion` で止める。
6. ダークもライトと同じだけ作り込む。
   色の反転で済ませない。

## 対象の環境

- 主に保証するのは、デスクトップの Chrome と iPhone の Safari である。
  Firefox、Android の Chrome、デスクトップの Safari は、`@smoke` を付けた E2E が通ることだけを見る。
  iPad の Safari は対象に含めない。
- 幅は 375、768、1280px を主にし、ライトとダークの両方で確かめる。
  375 と 768 は狭い幅と中間の幅の代表で、デスクトップの Chrome を縮めて見る。
  iPhone の Safari は、E2E の端末の既定の幅で見る。
- 幅 320px と 1440px では、どの状態でも横スクロールを出さない。
- 幅 320px は、端末の既定の幅ではなく、拡大表示などで生じる幅として扱う。
  閲覧と、ゲストに見える状態と、書き込みの通常の状態は、主の幅と同じに保証する。
  オーナーの操作の途中にだけ出る状態（長すぎる title や本文の案内、通知、操作の直後の知らせなど）では、横スクロールが出ないこと、操作が画面の内側に全部入ること、タッチ操作の端末ではタップの対象が `--tap-size` 以上であることだけを守る。
  折り返しや行の伸び縮みなどの見た目は問わない。
- 公開ページを支援技術で読めることは、下の「アクセシビリティ」の条件で守る。
  オーナーの編集、保存、通知の流れを VoiceOver などで操作することは、その条件を超えて作り込まない。
- iPad や iPhone に外付けのキーボードをつないだ操作は作り込まない。
  iPhone の E2E でだけキーボードの操作のテストが落ちるときは、デスクトップで通れば、その端末では skip してよい。
  パソコンのキーボードでの操作は対象に含める。

## 守る条件

### 見た目

- 見た目の値は `apps/web/src/theme.css` の token に置く。
  対象と例外の書き方は [AGENTS.md](../AGENTS.md) の規約にある。
- 同じ役割の要素は同じ見た目にし、focus、hover、押下の表示も揃える。
- 本文の幅は `--prose-width`（44.5rem）にし、エディタの本文（16px）で 1 行を全角 44 字までに収める。
  em にすると `.note` の 15px で測られて字数が減るので、rem で書く。
  本文の行間は `--line-height-prose`（1.8）で、エディタとスケルトンが同じ値を使う。
- Web フォントは使わず、端末のフォントで組む。
  和文と欧文が混ざっても崩さない。
- 画面の文言では、数と漢字や仮名の間を空けない（「3文字以上」「約1分前」「19:09に許可」）。
  欧文の語（token、UTC など）と、欧文の単位を付けた数（「10 MB」）は 1 語として扱い、和文との間を空ける。
- 数と単位を別の行に分けない。
  文節で切らない描画（iPhone の Safari）の普通の折り返しで分かれる所は、数と単位の間に WORD JOINER（U+2060）を置く。
- 空、読み込み中、エラー、長い title、多いタグ、大きい画像などのどれでも崩さない。
- 画像、コードブロック、通知、ダイアログなどを、ダークで周りより明るく目立たせない。

### 操作

- 読み込みや保存でレイアウトを動かさない。
- タッチ操作の端末では、タップの対象を `--tap-size`（44px）以上にする。
- タッチ操作の端末では、入力欄の文字を `--font-size-input`（16px）以上にし、iOS が focus でページを拡大しないようにする。
- ソフトウェアキーボードで caret を隠さない。
- エディタは日本語の変換を崩さない。
  守る条件は `packages/editor/src/ime.ts` の冒頭にある。
- 失敗したときは直し方の分かる案内を出し、入力した内容を残す。
- エディタの本文の中の部品は、caret を動かしても代わりにならない操作だけを Tab で止める。
  caret を動かすと記法が source で出て、同じことができる操作（タスクの checkbox、embed の「記法を編集」）は、Tab で止めない。
  caret では代わりにならない操作（callout の開閉、frontmatter の tag の chip）は、Tab で止め、Enter と Space で押せるようにする。
  Tab の順は文書の順で、caret の位置には合わせない。
  chip は文書の先頭にあり、caret が前にあることはまず無いので、caret より後ろに限ると届かなくなる。

### アクセシビリティ

- axe で serious 以上の違反を出さない。
  `apps/web/e2e/a11y.spec.ts` が検査し、既知の違反の一覧（`a11y-known.json`）は空に保つ。
- 本文と補助の文字のコントラストは、ライトとダークの両方で WCAG AA を満たす。
- 作成、検索、保存の失敗や衝突からの復帰を、キーボードだけで終えられるようにする。

## 確かめ方

- 描き終わった画面だけでなく、読み込み中、保存中、公開中などの途中の状態も見る。
  Playwright の `page.route` で API のレスポンスを遅らせると撮れる（`apps/web/e2e/sheet/scenes.sheet.ts` に例がある）。
- `pnpm e2e:sheet` で、明暗と幅 375、768、1280 の画面の一覧を見る。
- 幅 320、375、768、1280、1440 で横スクロールが出ないことは、`apps/web/e2e/layout.spec.ts` が確かめる。
- 数と単位が別の行に分かれないことは、`apps/web/e2e/number-wrap.spec.ts` が幅 320〜375 で確かめる。
  文言を足したり、普通の折り返しの要素に数と単位を入れたりしたら、そこに対象を足す。
- axe のコントラストの検査はライトでしか走らない。
  ダークの色を変えたら、コントラスト比を手で測る。
- 動きを足したら、`prefers-reduced-motion` で止まることを確かめる。
- フォールバック先のフォントの名前は、撮影からは見分けられない。
  Chromium では CDP の `CSS.getPlatformFontsForNode` で、実際に使われたフォントの名前を見る。
- フォントのレンダリング（`-webkit-font-smoothing` など）は headless の撮影には出ない。
  macOS の headed のブラウザで、指定を付けた場合と外した場合を並べて比べる。
